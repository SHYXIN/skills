先判定：用户的描述够不够直接开工。判定标准是你答不上其中之一——「用户指的东西是什么」「做成什么样算完成」。够开工就直接干活，本 skill 到此为止。

## 第一步：引导词是第一动作

判定不够开工后，你的第一条回复就是引导词本身——在用户填空之前保持零工具调用，所有研究和验证都留到填空之后。完成标准：引导词已发出，且本次回复没有工具调用。

## 第二步：生成引导词（一轮全给）

固定骨架五问，槽位语义固定、措辞按场景微调：

1. **这是什么？**——一个功能 / 一个报错 / 一个想法 / 一件任务（示例答案：`CodeBuddy 的输入建议功能`）
2. **用在哪、干嘛？**——哪个产品、哪段流程（示例：`终端里的对话输入框`）
3. **现在怎么表现？**——用户看到的行为或现象原样（示例：`输入框里有行灰字，回车就发出去了`）
4. **有什么约束？**（示例：`只能在空闲时出现`）
5. **期望变成什么样？**——做成什么样算完成（示例：`我打字它就消失，按 Tab 能填进输入框继续改`）

再按用户描述的领域追加 1-2 个贴题问题：软件功能加「这是哪家产品的哪个界面？」；报错加「报错原文和触发时机？」；想法/方案加「给谁用、解决谁的什么问题？」。

规则：全部编号、一轮给完；每题一两个词就能答完；每题带示例答案；用户原话已经回答过的题删掉，换成一句确认（如「我理解你指的是 X，对吗？」）。完成标准：用户一次性收齐全部问题。

## 第三步：组装可携带描述

用户填完后，把答案整理成一段结构化 Markdown（对象 / 场景 / 现状 / 约束 / 期望，领域细节原样保留），直接贴在聊天里，并说明这段可以复制给任何 agent 用。完成标准：用户整段复制走，另一个 agent 拿到就能开工。

只在聊天里输出；用户说「存一下」时才写成文件，沿用仓库既有的存放约定。

## 衔接 grill-one

对象锁定后若用户还要深挖方案细节，提一句「可以接 /grill-one 一次一问地磨」；用户不要就继续干活。分工：本 skill 管识别（引导词一轮全给），grill-one 管深挖（一次一问）。
