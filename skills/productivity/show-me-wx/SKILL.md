# 结果导览（show-me-wx）

用户想快速了解一段已完成工作的 shape。你的任务是当导览员：把成果摊开、画出来、给出游览路线——不是复述过程，不是写交接文档。

## 报告结构（节固定，内容自适应）

四节骨架，按实际产出裁剪：没有对应内容的节直接省略，不硬凑。

### ① 一句话总览

这轮工作干了什么，一句话。写成「产出了什么」而不是「做了哪些步骤」。

### ② 产物地图

所有值得看的产物，清单式：路径 / URL / 一行说明。有什么写什么——代码仓库写关键文件树（缩进树展示目录结构），调研写文档和链接，部署写服务器路径和访问入口，混合工作全列。

- 每个产物一行：`路径或URL` — 一句话说明它是什么、为什么值得看
- 目录结构用缩进树，只展开到「能看懂 shape」的深度，不逐文件罗列
- 产物多时按主题分组（如：文档 / 代码 / 部署 / 数据）

### ③ 图示

用 mermaid 画出成果的结构关系。规则：

- **默认 1 张总览图**：展示产物/模块间的整体关系，给人第一印象的 shape
- **节点超过约 10 个就拆**：1 张总览 + N 张局部图，绝不把 15+ 节点挤进一张图
- **每张图一个焦点**：数据流、部署拓扑、目录结构、模块依赖各是各的图，图带标题
- 没有值得画的关系结构就整节省略——不要为了凑节画一张空洞的图

### ④ 推荐路线

1–3 条按目的分的游览路线，告诉读者先看什么后看什么、每张图在路线的哪个位置。路线命名体现目的，例如：

- **5 分钟版**：只看最核心的 2–3 个产物
- **深挖版**：按依赖顺序过全部关键产物
- **演示版**：给别人讲这套成果时的展示顺序

路线写成语义串联（「先看 X 建立整体印象，再进 Y 看核心实现，Z 是部署入口」），不是干巴巴的编号列表。

## 可选落盘

参数含 `save` 时，把报告写成 markdown 文件。按顺序探测，取第一个命中的目录（目录不存在则先创建）：

1. 当前工作目录下有 `temp/` → 存 `<cwd>/temp/show-me/`
2. 当前工作目录下有 `tmp/` → 存 `<cwd>/tmp/show-me/`
3. 都没有 → 退回 OS 临时目录的 `show-me/` 子目录

文件名：`YYYY-MM-DD_HHMM_show-me_主题.md`。写完后把最终文件的**绝对路径**明确告诉用户。默认（无参数）纯对话输出，不落盘。

## 纪律

- **给指针，不复制正文**：报告里是路径、URL 和一行说明，不把产物内容搬进报告。
- **脱敏**：API key、密码、个人信息一律打码或略去。
- **面向人**：读者是用户本人，不是下个 agent——不需要给 AI 留指令，需要给人建立直观。
- **报告用中文**。
