# Loop Driver（环式自进化调度器）

把任务组织成一个自我改进的循环。每一圈：收目标 → 选组合 → 执行 → 记分 → 沉淀调权重。循环的"基因"是**调度权重**，不是 skill 内容。

## 设计边界（先读，别违背）

1. **skill 内容不可变**：任何单次任务、任何上下文，都不允许改写被调用 skill 的 SKILL.md。教训、偏好只进 ledger 和 weights。
2. **人趋近无人**：人不执行、不评估、不调参。只在两处出现——
   - **入口**：给一个目标（"我想要 X / 遇到什么问题"）。
   - **红线**：出现不可逆动作时，自动拦截找人对一眼。
3. **数据驱动**：权重只由记分结果改变，禁止拍脑袋改权重。
4. **一次一个目标**：loop 同时只驱动一个目标。多个目标排队。
5. **没有证据不记正分**：验证信号达标才算正分（复用 closed-loop 的闭环标准）。

## 循环协议（五步）

### 第一步：收目标（入口）

- 从用户拿到**目标 + 场景标签**。场景标签描述"这是什么类型的事"，例：`代码修复` / `文档沉淀` / `方案调研` / `环境搭建` / `复盘分析`。
- 场景标签未知时，由 AI 按目标内容判定，写进 ledger。
- 一个目标一个场景；拿不准问一次（一次一个问题），不反复问。

### 第二步：选组合

- 读 `weights.md`，选该场景下**累计分最高**的组合（并列时选"试过次数更多"的；都没试过用候选表默认组合）。
- 没找到对应场景的权重 → 用默认组合候选表里该场景最接近的默认项，并在 ledger 记 `新场景首跑`。
- 输出本轮计划：`场景 / 所选组合 / 理由（引用权重或默认）`，一句话给用户确认；用户说"换"就换一个候选再确认，不进入循环正文。

### 第三步：执行

- 按组合里的顺序调用各 skill（skill 即你仓库里已有的能力，按它们的 SKILL.md 执行）。
- 执行中**不动任何 skill 内容**。外部信息变了、组合跑不通 → 停止，回到第二步重选（记负分），不要硬扛。
- 不可逆动作（花钱、发布、删除、改共享配置、发消息）→ 到红线：列证据、找用户对一眼，用户确认才执行；不确认则记负分并收尾。

### 第四步：记分

执行完立刻用闭环信号判定正负分，**证据先行**：

- **正分**：有可观察的验证信号（测试过 / 文件落盘 / 收到回复 / 页面能打开 / 结论经得起真实案例套用 / 用户明确确认）。
- **负分**：卡壳、返工、被用户纠正、不可逆动作被拦、组合中途跑不通、无证据硬宣称完成。
- 拿不准（说不清有没有真正验证）→ 记负分偏保守，**不问用户**（人在环外，不评估）。

记分只影响 weights，**不写回任何 skill 内容**。

### 第五步：沉淀 + 调权重

- 在 ledger 追加一条记录（见下方 ledger 结构），然后更新 weights：
  - 正分 → 该组合该场景 +1。
  - 负分 → 该组合该场景 -1；**连续 2 次负分** → 该组合降为不可选，换用下一候选；被降权的组合记录在 weights 的"禁用区"，不再默认选中。
  - 某组合同场景**连续 3 次正分** → 标记为 `默认`（候选顺序里排最前），仍是数据驱动，不写死 skill。
- 沉淀位置运行时定位（见下）。

## 数据文件（运行时定位，不硬编码路径）

- **ledger**：`loop-log/ledger.md` —— 只追加的历史记录。
- **weights**：`loop-log/weights.md` —— 当前权重与默认组合，唯一可写的数据文件。

定位规则（与 doc-append-log 的 locate 思路一致）：
1. 当前工作目录有 `loop-log/` → 用它。
2. 找到用户项目的 `loop-log/`（向用户确认或用项目根）。
3. 都没有 → 在当前目录建 `loop-log/`，初始化两个文件。

### ledger.md 结构（只追加）

```
## YYYY-MM-DD HH:MM <目标简述>

- 场景: <标签>
- 组合: <skill1 → skill2 → …>
- 结果: 正分 / 负分
- 证据: <可观察信号 / 失败原因>
- 教训: <一句话，可空>
```

每条一律追加在末尾，**不改写旧记录**。

### weights.md 结构

```
# 场景: 代码修复

| 组合 | 累计分 | 连续正 | 连续负 | 状态 |
| --- | --- | --- | --- | --- |
| skill-a → skill-b | +3 | 2 | 0 | 默认 |
| skill-c → skill-a | -2 | 0 | 2 | 禁用 |

# 场景: 文档沉淀
…
```

- `状态`：`默认` / `候选` / `禁用`。
- 选择规则：只从 `候选` 与 `默认` 里选，按累计分降序，并列按试过次数，`默认` 优先。

## 默认组合候选表（新场景首跑参考）

| 场景 | 默认组合 |
| --- | --- |
| 代码修复 | verify-run →（修复）→ verify-run（复验） |
| 文档沉淀 | doc-append-log |
| 方案调研 | consensus-tech-research → next-step |
| 环境搭建 | verify-run（探测）→ 对应搭建 skill |
| 复盘分析 | retro-wx |
| 通用闭环 | closed-loop → next-step |

候选表只用于首跑种子，圈数多了以 weights 为准。

## 红线

- 不许改写任何 skill 的 SKILL.md（含本 skill 自己——本 skill 内容同样不许被单次任务改写）。
- 没有证据不许说"闭环了""进化了"。
- 人不评估——记分不问用户；只有入口收目标、红线确认不可逆动作才找人。
- 权重只能由记分改变，禁止手动调。
- 大事（共享状态 / 不可逆）必须用户确认才算正分，否则负分收尾。

## 与小循环/大循环

- **小循环**：一次目标从收走到调权重，一圈完成。
- **大循环**：ledger 越攒越厚 → 权重越选越准 → 用户（目标源）越多 → 场景覆盖越广 → 环转得更大。大循环不需要额外动作，它只是小循环的累积。
