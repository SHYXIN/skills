# agent-tdd — agent 行为的红绿循环

代码 TDD 的测试是写死的断言；agent 的「代码」是 md/skill 文案，行为由 LLM 现场生成，断言写不死。本 skill 用**行为案例集**替代断言：每条案例 = 一条用户输入 + 预期行为标记（必现关键词/禁词/长度）。执行器负责批量跑与判分（见 `references/executors.md`），本 skill 只管纪律。

## 核心循环（双轨）

```
           新行为（新增意图/新裁决/新产物章节）
           ┌─────────────────────────────┐
           │ ① 写案例 → ② 跑红 → ③ 改 md/skill → ④ 跑绿 │  案例先行轨
           └─────────────────────────────┘
           存量改动（改措辞/修规则/发版前）
           ┌─────────────────────────────┐
           │ ① 跑基线 → ② 改 → ③ 再跑 → ④ diff 无退步  │  回归护栏轨
           └─────────────────────────────┘
```

选轨判据：**这个行为是「还没有」还是「已有但不能坏」**。还没有→先行轨；已有→护栏轨。大改动两轨都走：先跑基线，再为新行为补案例跑红，改完一轮全绿收口。

## 步骤

### 1. 把行为预期翻译成案例

新行为的案例集就是它的可执行 spec——写不出案例 = 行为还没想清楚，先回 grilling。

案例集与被测 md/skill **同仓存放**（放其 `eval/` 目录），不进 skill 仓。格式跟随执行器（典型字段：`user_message` / `required_markers` / `forbidden_markers` / `answer_max_chars`）。

**案例写法纪律**（LLM 抖动的第一道防线，优先级高于一切补救）：

- `required_markers` 用**行为性关键词**，不用精确句式。好例子：产物固定章节名（如「结论」）、状态标签（如「已确认」）、结构化字段名（如 `status`）、路由分支词。坏例子：整句期望文案、措辞顺序
- `forbidden_markers` 打**具体禁词**：裸状态码、被裁决废弃的措辞变体、不该出现的产品名
- **一条案例只验证一个行为点**。想测「先问后答」和「不提登录」就拆两条
- 长度上限只用于防跑飞的粗边界（如「一句话介绍 ≤100 字」），不当语义断言

### 2. 跑红 / 跑基线

**跑红默认可跳过**：默认只写案例、不真跑红，直接进步骤 3 改 md/skill（红检的执行成本高——逐 case 真实建会话，一次十几分钟起步）。案例集照常交付，收尾时作为可复跑资产留给下一次改动或用户自测。

想真跑红时用户点名即可（「红检跑一下」「先跑红再改」）；agent 主动建议跑红仅限一种情况：改动会**翻转既有裁决**（改路由分支、删门禁、换产物契约），且用户没有给出真实失败证据时。

- 先行轨（跑了的话）：改 md **之前**跑一轮，新案例必须红（当前 agent 做不到 = 案例有效；直接绿 = 案例写错了或行为已存在，回步骤 1 修案例）
- 护栏轨：改之前跑一轮当基线，label 用 `baseline-<日期>`

### 3. 改 md/skill

正常开发。同一文案多处同步维护的，在同一 commit 内改齐再进入下一步，别带着半同步状态跑绿。

### 4. 跑绿 / 再跑 + diff

跑绿**默认同样可跳过**（成本同跑红）；与跑红独立决定——跳了红检不等于必须跳绿检，反之亦然。

agent 主动建议跑绿（护栏轨或先行轨）仅限一种情况：改动会**翻转既有裁决**（改路由分支、删门禁、换产物契约）且用户没给真实验证证据时——裁决翻转的回归主要靠绿检抓，此时绿检不该静默跳过。

- 先行轨（跑了的话）：新案例全绿才算改完。**跳过红检后直接绿要按可疑处理**——案例从未被证明「能红」，先查案例有效性（是不是写松了、行为是不是本来就有），再庆祝改好
- 护栏轨：跑第二轮后 diff 两轮，**逐 case 看**「新增红」和「消失绿」

### 5. flaky 仲裁（唯一允许的复跑）

agent 会抖动：diff 里出现的「新增红/消失绿」**不直接定罪**，用执行器的单 case 复跑能力仲裁一次——复跑绿 = 抖动，记录不管；复跑仍红 = 真退步，回步骤 3。红期（步骤 2 先行轨）的案例不适用仲裁：跑红是预期行为，没有定罪问题。

### 6. 红期排查（改不动时）

绿不了别急着反复改 md——先用会话取证看 agent **实际收到了什么注入、实际调了什么工具**，区分「规则没写对」和「规则没被读到」。先建反馈回路，再动手。

## 收尾

- 案例集留在被测仓，作为下一次改动的基线资产（护栏轨的输入就是它）
- 跳过红检/绿检时，交付说明里写明「案例集路径 + 未执行」，用户想验证时随时可跑
- 两轮 run 的 diff 报告路径写进交付说明（MR 描述/会话结论），证据可回溯

## Backlog

- **知识库/本体健康巡检** skill：孤立节点、规则冲突、多处同步漂移的主动扫描。等本 skill 真实使用积累摩擦后再立项，勿提前空转。
