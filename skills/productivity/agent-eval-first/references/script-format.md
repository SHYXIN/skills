# 对话剧本格式（唯一源）

一个剧本文件 = 一个行为主题的案例集合，存放在被测仓 `eval/` 目录（如 `eval/script-<主题>.md`）。人直接读写这个文件；案例 JSON 与对话 HTML 全部由 `scripts/compile.py` 编译生成，衍生品永不手改。

## 语法

```markdown
# <剧本标题>

meta: 被测对象说明（可选，编译时写入 HTML 页头，不进 JSON）

## case: <case_id>　<一句话说明测什么>

**用户**：<用户输入原文>

**AI**：
<完整预期回复原文——写全，给评审看，也是判分点出处>

```expected
required: <关键词1>, <关键词2>
forbidden: <禁词1>
max_chars: 2000
```

tags: <标签1>, <标签2>
```

规则：

- `## case:` 开一个案例；`case_id` 用 ASCII 短横线式（如 `route-repair-001`）
- `**用户**:` 一行；`**AI**:` 后跟多行回复原文（直到 ```expected 围栏为止）
- ```expected 围栏内是判分标注：`required` / `forbidden` 逗号分隔，`max_chars` 数字（0 或缺省 = 不限）
- `tags:` 行可选，逗号分隔
- 空行分隔各元素；`<!-- -->` 注释编译时忽略

## 编译

```bash
python <skill安装目录>/agent-eval-first/scripts/compile.py <剧本.md> -o <被测仓>/eval/
```

产出：`<case集名>.questions.json`（执行器格式）+ `<case集名>.preview.html`（对话预览，单文件自包含）。

## 写法纪律（LLM 抖动的第一道防线）

- **预期回复写完整对话原文**——把「好」写成看得见的回复，这是给评审看的，也是判分点的出处。不写「应包含 XXX 的说明」式断言描述
- `required` 用**行为性关键词**：产物固定章节名、状态标签、结构化字段名、路由分支词。不用精确句式、不规定措辞顺序
- `forbidden` 打**具体禁词**：裸状态码、被裁决废弃的措辞变体、不该出现的产品名
- **一条案例只验证一个行为点**。想测「先问后答」和「不提登录」就拆两条
- 长度上限（`max_chars`）只用于防跑飞的粗边界，不当语义断言
