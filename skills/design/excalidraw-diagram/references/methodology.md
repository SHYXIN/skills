# 方法论：图要"论证"，不是"陈列信息"

> 改编自 coleam00/excalidraw-diagram-skill 的核心设计哲学。

一张图不是"排好版的文字"。它是一个**视觉论证**——用形状、位置、连线把文字说不清的关系、因果、流向呈现出来。**形状本身就应该是含义。**

## 核心原则

- **形状承载语义**：因果用箭头指向、层级用嵌套区域、对比用并列色块、时间用自上而下。不要只是把句子塞进方框。
- **少即是多**：宁可少数几个大方块，也不要一堆碎元素。先想"这张图要论证一句话是什么"，再决定画什么。
- **一眼可读**：读者 3 秒内应能看出主线。若需要读文字才懂结构，就该重新排。

## 布局规则

- 最小带标签形状：**120×60**。
- 元素之间最小间距：**20-30px**。
- 单向排列（横向或纵向选一个当主线），避免来回折线。
- 背景分组用大矩形 + `opacity: 30`，把相关组件框进去，组标题用小号 text 放左上角。

## 字号规则

- **28+**：图标题
- **20**：形状标签、一级标题
- **16-18**：正文、描述
- **14**：最小（仅用于次要注释）
- **绝不低于 14**

## 明暗模式

**浅色（默认）**：背景透明/白，文字用深色（`#1e1e1e`，最浅到 `#757575`）。

**深色**：在数组**第一个**放一块超大深色背景板，然后用深色填充 + 浅色文字：

```json
{ "type": "rectangle", "id": "darkbg", "x": -4000, "y": -3000, "width": 10000, "height": 7500, "backgroundColor": "#1e1e2e", "fillStyle": "solid", "strokeColor": "transparent", "strokeWidth": 0 }
```

深色下文字用 `strokeColor` 指定：主文字 `#e5e5e5`、次要 `#a0a0a0`。

## 绘制顺序

数组顺序 = z 轴顺序。渐进式输出：

```
相机 → 背景区域 → 形状1 → 形状1文字 → 箭头1 → 箭头1文字 → 形状2 → ...
```

先画背景板，再画内容；文字紧跟它的形状；箭头紧跟它连接的两个形状之后。

## 常见坑

- **忘了绑定**：箭头画了但没连到形状上，拖动时箭头不跟随。绑定箭头时记得同时写形状的 `boundElements`。
- **相机比例错**：`cameraUpdate` 必须 4:3，否则 CLI 报警告。
- **文字溢出**：`label` 文字太长会超出框，要么放大框，要么换行（用 `\n`）。
- **emoji**：手写字体渲染不出来，别写。
- **箭头 points 当绝对坐标**：`points` 是相对箭头 `x, y` 的偏移，不是绝对位置。
