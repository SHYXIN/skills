# Lesson 完成检查清单

每生成或更新一节主线 lesson 后，必须检查本清单。目标是确保 lesson 可复习、示例可运行、学习区状态一致。

## HTML

- `lessons/000N-{slug}.html` 已生成或更新。
- HTML 引用了 `../assets/lesson.css`。
- 有 lesson 元信息：编号、主题、节奏、预计阅读时间。
- 有页内目录，并且目录链接指向真实存在的章节 `id`。
- 有稳定章节：为什么需要它、它是什么、直觉类比、核心结构、最小例子、常见误解和边界、示例项目（实操型）或架构观察（概念型）、自检问题、下一步。
- 直觉类比说明了哪里像、哪里不像。
- 字符图按 `../DIAGRAM-STYLE.md` 规范画（盒线字符、宽度对齐、≤80 列），放在 `<pre><code>` 中，并有说明文字。
- 不存在空链接；不存在的上一课、下一课、参考资料链接要省略。
- 页面可单独打开，不依赖外部 CDN。

## 示例 / 架构观察

按 `MISSION.md` 的主题性质二选一检查：

**实操型（示例项目）：**

- lesson 有“示例项目”章节，链接到 `examples/000N-{slug}/`。
- 示例目录有 `README.md`。
- 示例有可执行入口，例如 `demo.py`、`demo.ts`、`demo.js` 或 `demo.sh`。
- 示例 README 写清：对应 lesson、目标、运行命令、预期结果、修改实验、验证状态。
- 能运行就实际运行并记录结果；不能运行就降级（换等价示例或改示意代码）并标注原因。
- 示例小到 5-10 分钟能读完和跑完。
- 示例不复制原仓库大段代码，不创建大型 demo app。
- 依赖使用 `examples/` 级别共享环境，不在单个示例里创建 `.venv` 或 `node_modules`。

**概念型（架构观察）：**

- lesson 有“架构观察”章节：核心架构图/对比矩阵（按 DIAGRAM-STYLE 规范）+ 值得去读的真实文件/资料清单。
- 不存在 `examples/` 目录（或确认它不再被引用）。
- 清单里的文件/资料路径真实存在，写清读什么、对应 lesson 哪个机制。
- 环境限制已写入 lesson（如“演示需 Linux，本机 Windows 仅示意”）。

**无论哪种：**

- 形态与 `MISSION.md` 的主题性质一致；不一致时先确认是否要改 mission。

## 学习区状态

- `OUTLINE.md` 已更新当前位置和下一步。
- `MISSION.md` 没有被无确认地改写；主题性质判定（概念型/实操型）已记录。
- `RESOURCES.md` 记录本节用过的可信来源。
- `GLOSSARY.md` 只加入用户已经能正确使用的术语。
- 只有重要理解、误区修正或目标变化才写 `learning-records/`。
- 旁路问题没有被合并进主线 lesson，除非用户明确要求。

## 对话收尾

- 告诉用户生成或更新了哪些文件。
- 告诉用户怎么打开 HTML lesson。
- 实操型：告诉用户怎么运行示例，说明是否已验证；概念型：告诉用户架构观察清单里值得先读的资料。
- 回到 `OUTLINE.md` 的当前位置，询问下一步是继续主线、深入某节，还是调整大纲。
