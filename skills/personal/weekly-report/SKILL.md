# 周报生成器 (weekly-report)

把一份**多人例会全文**转换成**某一个人**的周报邮件正文，便于复制后直接发邮件。

## 适用场景
- 用户发来一份例会记录（钉钉/飞书导出的文本，含「本周工作进展」「下周计划」等按人分组的内容）。
- 用户希望只拿到**自己（或指定成员）**那一份周报，而不是全员的。

## 输入约定
1. 优先读取**用户提示词里粘贴的例会全文文本**。
2. 若用户提示词里**只给了一个文件路径**（如 `tmp/lihui.txt` 或绝对路径，且不是例会正文），用 Read 工具去读那个文件，把内容当作例会全文。
3. 目标成员：
   - 默认 **王鑫**。
   - 若调用时带了参数（如 `/weekly-report 杨杰`），以参数为准；也可在对话中说明「帮我生成 杨杰 的周报」。

## 例会全文的典型结构（用于定位）
例会全文通常长这样（钉钉/飞书导出）：
- `风险求助`：风险与求助。
- `上周计划事项`：按人列出上周计划及完成勾选（☑/☐）。
- `本周工作进展`：按人分组，每人有 `本周内容`（a/b/c… 或 1/2/3…）和 `下周计划`。
- `下周计划-待办`：带 @ 负责人的待办。
- `其他（想法、长期事项）`：空或零散想法。

**提取目标成员的步骤：**
1. 在全文里找到目标成员的名字作为小标题的那一段（如 `王鑫` 单独成行，其下紧跟 `本周内容` / `下周计划`）。
2. 取该段下的 `本周内容`（或「本周进度」「本周工作」等同义标题）作为**本周工作进度**。
3. 取该段下的 `下周计划`（或「下周计划-待办」中 @该成员 的项）作为**下周计划**。
4. 若某人段里出现「学习 xxx」「调研 xxx」「研究 xxx」等自学/新技术类条目，记下，用于起草个人思考。
5. 不同周会格式可能略有差异：以「成员名 + 其下的工作内容/计划」为锚点，灵活定位，不要死扣字段名。

## 输出格式（严格复刻用户既有周报风格）
整段输出如下，**直接可复制进邮件**：

```
【周报】<成员名> <本周日期或周次，如 2026-08-10 ~ 08-16 或 2026-W33>

一、本周工作进度
   1.1 <压缩后的工作点，动宾短语，一行一个>
        - <关键细节/产出>
   1.2 ...

二、下周计划
   2.1 <计划项>
        - <细节>

三、新技术 / 个人思考
   1.1 <基于本周真实工作起草的第一人称反思；若本周有自学新技术则点出；标注【可改】>
```

格式要点：
- 用 `一、二、三、` 三级，`1.1 / 1.2` 子编号。
- 本周进度用**精炼的动宾短语**，保留关键产出/数据（如「速度优化 50%~70%，由 8~10 分钟降到 3-4 分钟」）。
- 下周计划同理，保留 @对象、依赖项。
- 第三栏基于本周内容**起草**一段个人思考：抓技术收获、踩坑、方法论感悟；若本周有「学习/调研 xxx」，把它展开成你的体会。用第一人称，标注 `【可改】`，提示用户发送前可润色。
- 不要包含「风险求助」「上周计划完成度」等栏目（用户周报不含这些）。

## 注意事项
- 只输出目标成员的周报，不夹杂其他人的内容。
- 忠实于例会原文，不编造未提及的进展；个人思考可基于事实引申，但明确标注【可改】。
- 语言中文，简洁，贴合用户既有周报语气。
- 若原文找不到目标成员，提示用户并列出全文出现过的成员名供选择。
- 输出后即结束，不要追加多余解释。
